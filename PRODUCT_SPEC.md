### Ключевые алгоритмы (уже реализованы)
- **SafeToSpend v3.3**: IQR-медиана зарплаты → резервирование регулярных платежей → дневной лимит
- **Recurring Payment Detection**: кластеризация по сумме ±15% и дню ±7 дней за 6 мес.
- **Groq Categorization**: батчевая категоризация транзакций при импорте (30 шт./запрос)
- **CloudStorage Sync**: chunked (3500 chars/key), sequential write, merge-on-read, retry×3

### Критические проблемы текущей реализации

| Проблема | Приоритет | Описание |
|----------|-----------|---------|
| API-ключ Groq захардкожен в клиенте | 🔴 CRITICAL | `gsk_cRht0YjK6MMoLUHOJF0x...` виден в исходниках |
| Бэкенд-сервисы — заглушки | 🔴 HIGH | Все данные только локально, нет серверной части |
| SafeToSpend: формула с ошибками | 🔴 HIGH | Последний день месяца завышает сумму; перерасход скрыт нулём; `safeToday` не учитывает уже потраченное сегодня — см. [`ALGORITHM_SPEC.md`](ALGORITHM_SPEC.md#alg-003-safetospend-v4) |
| Категоризация: ~30% транзакций = `other_exp` | 🔴 HIGH | Локальный классификатор неполный; Groq не получает сумму; JSON-парсер падает молча — см. [`ALGORITHM_SPEC.md`](ALGORITHM_SPEC.md#alg-002-категоризация-транзакций-v2) |
| Регулярные платежи: подписки не детектируются | 🟡 MEDIUM | `MIN_AMOUNT=5000` отсекает Netflix 799₽; нет staleness-check — см. [`ALGORITHM_SPEC.md`](ALGORITHM_SPEC.md#alg-001-детекция-регулярных-платежей-v2) |
| CloudStorage лимит ~4KB/ключ | 🟡 MEDIUM | При большой истории (1000+ транзакций) может не влезть |
| Нет дедупликации при импорте | 🟡 MEDIUM | Повторный импорт одного файла дублирует транзакции |
| Бюджеты не синхронизируются в CloudStorage | 🟡 MEDIUM | Только transactions + goals + streak |
| P2P-переводы и наличные не категоризируются | 🟡 MEDIUM | Перевод другу и снятие наличных — реальные расходы с конкретной целью. Нужен Groq + обязательный PostImportWizard, а не заглушка `other_exp` — см. [`ALGORITHM_SPEC.md`](ALGORITHM_SPEC.md#alg-004-политика-переводов-и-снятий-наличных) |
| Голосовой ввод отключён в TG WebView | 🟢 LOW | Намеренно, но стоит найти альтернативу |

## 1. Продуктовая концепция

### Проблема
Существующие финансовые приложения — это либо скучные таблицы (требуют дисциплины), либо сложные инструменты (требуют экспертизы). Пользователь не хочет быть бухгалтером — он хочет понять, **можно ли купить кроссовки сегодня**, и получить ответ за 3 секунды.

### Решение
**FinWise** — персональный финансовый ассистент в Telegram, который:
1. **Знает твои деньги лучше тебя** — импортирует историю из банка, автоматически категоризирует, находит паттерны
2. **Говорит на человеческом языке** — не "норма сбережений 12%", а "можешь потратить 1 840 ₽ сегодня"
3. **Действует проактивно** — не ждёт вопроса, сам предупреждает о рисках и возможностях
4. **Встроен в Telegram** — там, где пользователь уже есть, без отдельного приложения

### Позиционирование
> "Умный друг, который разбирается в финансах и всегда под рукой в Telegram"

### Целевая аудитория
- **Первичная**: 25–35 лет, наёмные работники с зарплатой 60–200k ₽/мес., активные пользователи Telegram
- **Вторичная**: фрилансеры с нерегулярным доходом, молодые специалисты 22–28 лет

### Метрики успеха

| Метрика | Определение | Baseline | Цель (3 мес.) |
|---------|-------------|----------|---------------|
| **North Star: DAU/MAU** | Доля активных пользователей в день | — | ≥ 25% |
| Retention D7 | % пользователей, вернувшихся на 7-й день | — | ≥ 40% |
| Onboarding completion | % завершивших онбординг | — | ≥ 70% |
| AI chat engagement | % пользователей, задавших ≥1 вопрос в неделю | — | ≥ 35% |
| Import adoption | % пользователей, импортировавших выписку | — | ≥ 50% |
| Streak 7+ days | % пользователей со стриком ≥7 дней | — | ≥ 20% |

**Guardrail метрики** (не должны ухудшаться):
- Crash rate < 1%
- AI response time < 3s (p95)
- CloudStorage sync success rate > 95%

## 3. Функциональные требования

### 3.1 Dashboard (Главный экран)

**Текущее состояние**: ✅ Реализован

**Что доработать**:

#### F-001: Проактивные AI-инсайты на Dashboard
**Проблема**: AI-баннер показывает статичный текст, не меняется при каждом открытии
**Решение**: Ротация 5–7 персонализированных инсайтов на основе данных пользователя

**User story**: Как пользователь, я хочу видеть новый полезный инсайт каждый раз, когда открываю приложение, чтобы узнавать что-то новое о своих финансах

**Acceptance criteria**:
1. Инсайт меняется при каждом открытии Dashboard (не чаще 1 раза в час)
2. Инсайты персонализированы: используют реальные данные пользователя
3. Типы инсайтов: аномальная трата, прогресс к цели, сравнение с прошлым месяцем, предупреждение о регулярном платеже, совет по экономии
4. Клик на инсайт открывает релевантный экран или AI-чат с контекстом
5. Если данных нет — показывается онбординг-подсказка

**Метрика**: CTR на AI-баннер ≥ 15%

---

#### F-002: Виджет "Регулярные платежи" на Dashboard
**Проблема**: Пользователь не видит, какие платежи ожидаются в ближайшие 7 дней
**Решение**: Карточка "Ближайшие платежи" под SafeToSpend

**Acceptance criteria**:
1. Показывает платежи, ожидаемые в ближайшие 7 дней (из `recurringPayments`)
2. Только подтверждённые пользователем (`confirmedByUser: true`) или добавленные вручную
3. Каждый платёж: иконка, название, сумма, дата
4. Если платежей нет — виджет скрыт
5. Клик → переход на экран управления регулярными платежами

### 3.2 Транзакции

**Текущее состояние**: ✅ Базовая реализация

**Что доработать**:

#### F-003: Редактирование транзакции
**Проблема**: Нельзя отредактировать добавленную транзакцию
**Решение**: Свайп влево на транзакции → кнопки "Изменить" / "Удалить"

**Acceptance criteria**:
1. Свайп влево на транзакции в списке открывает action-кнопки
2. "Изменить" открывает форму с предзаполненными данными
3. "Удалить" показывает confirm-диалог
4. После удаления — анимация исчезновения, обновление SafeToSpend
5. Изменения синхронизируются в CloudStorage

---

#### F-004: Поиск и фильтрация транзакций
**Проблема**: При 500+ транзакциях нет способа найти нужную
**Решение**: Строка поиска + фильтры по категории, типу, периоду

**Acceptance criteria**:
1. Поиск по описанию транзакции (debounce 300ms)
2. Фильтр по категории (мультиселект)
3. Фильтр по типу: доходы / расходы / переводы
4. Фильтр по периоду: текущий месяц / прошлый месяц / 3 месяца / всё время
5. Активные фильтры показываются как чипы с возможностью сброса
6. Пустое состояние при отсутствии результатов

---

#### F-005: Дедупликация при импорте
**Проблема**: Повторный импорт одного файла создаёт дубликаты
**Решение**: Хэш-проверка по (date + amount + description) перед добавлением

**Acceptance criteria**:
1. При импорте каждая транзакция проверяется на дубликат по ключу `date|amount|description`
2. Дубликаты пропускаются, счётчик `skipped` увеличивается
3. В результате импорта показывается: "Импортировано: X, Пропущено дубликатов: Y"
4. Пользователь может принудительно импортировать дубликаты (чекбокс "Включить дубликаты")

---

### 3.3 AI-чат

**Текущее состояние**: ✅ Реализован, но есть критические проблемы

**Что исправить**:

#### F-006: Перенос API-ключа Groq на бэкенд
**Проблема**: Ключ `gsk_cRht0YjK6MMoLUHOJF0x...` захардкожен в клиентском коде — КРИТИЧЕСКАЯ УЯЗВИМОСТЬ
**Решение**: Все запросы к Groq идут через `ai-service` на бэкенде

**Acceptance criteria**:
1. Клиент отправляет запрос на `/api/ai/chat` с сообщением и userId
2. `ai-service` хранит ключ в env-переменной, делает запрос к Groq
3. Клиент не имеет доступа к ключу
4. Rate limiting: не более 20 запросов/мин на пользователя
5. Fallback на `smartResponses.ts` при недоступности бэкенда

---

#### F-007: Контекстные действия из AI-чата
**Проблема**: AI даёт советы, но пользователь должен сам идти и выполнять их
**Решение**: AI может предлагать кнопки-действия прямо в чате

**Acceptance criteria**:
1. AI-ответ может содержать action-кнопки: "Установить лимит", "Создать цель", "Посмотреть аналитику"
2. Клик на кнопку выполняет действие или открывает нужный экран
3. Кнопки рендерятся как отдельный компонент под текстом сообщения
4. Не более 3 кнопок в одном сообщении
5. Кнопки исчезают после нажатия

**Формат ответа AI с кнопками** (JSON в конце ответа):
```json
{"actions": [{"label": "Установить лимит на кафе", "route": "/budget", "params": {"category": "cafe"}}]}
```

---

#### F-008: История чата — персистентность
**Проблема**: История чата не синхронизируется в CloudStorage (только в localStorage)
**Решение**: Включить `aiMessages` (последние 20) в CloudPayload

**Acceptance criteria**:
1. Последние 20 сообщений AI-чата включаются в CloudStorage payload
2. При открытии на новом устройстве история восстанавливается
3. Старые сообщения (>20) хранятся только локально
4. Кнопка "Очистить" удаляет историю и из CloudStorage

### 3.4 Аналитика

**Текущее состояние**: ✅ Базовая реализация

## 4. Нефункциональные требования

### Производительность
- First Contentful Paint < 1.5s (в Telegram WebView)
- SafeToSpend расчёт < 100ms (даже при 2000 транзакциях)
- AI-ответ < 3s (p95)
- Импорт 1000 транзакций < 30s (включая Groq-категоризацию)

### Надёжность
- Offline-first: все основные функции работают без интернета (кроме AI-чата)
- CloudStorage sync: retry×3 с exponential backoff
- Graceful degradation: если бэкенд недоступен → работа с localStorage

### Безопасность
- API-ключи только в env-переменных сервисов
- Telegram initData валидируется на сервере
- Данные пользователя изолированы по userId
- HTTPS everywhere
- Нет хранения финансовых данных в открытом виде на сервере (шифрование at rest)

### Совместимость
- iOS 15+ (Telegram WebView)
- Android 8+ (Telegram WebView)
- Telegram Desktop (ограниченный CloudStorage)
- Минимальная ширина экрана: 320px

### Алгоритм SafeToSpend (v4 — см. [`ALGORITHM_SPEC.md`](ALGORITHM_SPEC.md#alg-003-safetospend-v4))

> ⚠️ Не менять без согласования. Полная спецификация изменений — в [`ALGORITHM_SPEC.md`](ALGORITHM_SPEC.md).

```
budget = IQR-медиана месячных зарплат (последние 12 мес.)
       → fallback: thisMonthIncome
       → fallback: медиана исторических доходов
       → бонусы и 13-я зарплата (>2x медианы) исключаются

alreadySpent = сумма expense-транзакций текущего месяца
               (без transfer между своими счетами;
                P2P-переводы и снятия наличных ВКЛЮЧАЮТСЯ)

spentToday   = сумма expense-транзакций за сегодня

reservedUpcoming = сумма recurring payments с confidence='high'/'medium'
                   И confirmedByUser=true,
                   где dayOfMonth > сегодня
                   И нет matching expense ±15% в этом месяце
                   ⚠️ ТОЛЬКО подтверждённые пользователем платежи резервируются

remaining  = budget - alreadySpent - reservedUpcoming  ← может быть < 0 (перерасход)
daysLeft   = daysInMonth - dayOfMonth + 1              ← включая сегодня
daysAhead  = max(1, daysLeft - 1)                      ← дней после сегодня
safePerDay = remaining / daysAhead
safeToday  = safePerDay - spentToday                   ← может быть < 0
```

**Ключевые изменения v4 vs v3.3:**
- `remaining` больше не обрезается `max(0, ...)` — перерасход показывается красным
- `daysLeft` включает сегодня, деление на `daysAhead` (без сегодня) — нет завышения в последний день
- `safeToday` вычитает уже потраченное сегодня — актуальное число в течение дня
- Резервируются ТОЛЬКО `confirmedByUser=true` платежи — пользователь валидирует перед вычетом

### Риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Groq API лимиты при росте пользователей | Высокая | Высокое | Rate limiting + кэширование ответов + fallback |
| CloudStorage переполнение (>4KB/ключ) при большой истории | Средняя | Среднее | Лимит 500 транзакций в CloudStorage, остальное только на сервере |
| Telegram изменит политику Mini Apps | Низкая | Критическое | Нет митигации, это платформенный риск |
| Пользователи не доверяют хранению финансовых данных | Средняя | Высокое | Прозрачность: "данные хранятся у вас", шифрование, privacy policy |
| Сложность онбординга отпугивает пользователей | Средняя | Высокое | A/B тест: 3-шаговый vs 6-шаговый онбординг |
| Импорт не работает для нового формата банка | Высокая | Среднее | Универсальный CSV-парсер как fallback |

## 10. Глоссарий

| Термин | Определение |
|--------|-------------|
| **SafeToSpend** | Сумма, которую пользователь может потратить сегодня без риска выйти за бюджет месяца |
| **Recurring Payment** | Регулярный обязательный платёж (аренда, подписки, кредит), автоматически обнаруженный или добавленный вручную |
| **CloudStorage** | Telegram CloudStorage API — хранилище до 1024 ключей по 4096 байт на пользователя |
| **Streak** | Серия дней подряд, когда пользователь добавлял транзакции или открывал приложение |
| **IQR-фильтр** | Interquartile Range — метод удаления выбросов: значения вне [Q1−1.5·IQR, Q3+1.5·IQR] исключаются |
| **PostImportWizard** | Пошаговый мастер после импорта выписки: уточнение категорий + настройка бюджета |
| **initData** | Строка от Telegram WebApp SDK, содержащая данные пользователя и подпись для верификации |
| **MCC** | Merchant Category Code — код категории торговца в банковских транзакциях (ISO 18245) |
