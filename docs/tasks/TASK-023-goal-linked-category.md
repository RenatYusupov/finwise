## 📋 ТЗ (Product Manager)

### Проблема пользователя

Цели существуют изолированно от расходов. Пользователь создаёт цель «Накопить на отпуск», но приложение не связывает её с категорией «Путешествия». Нет возможности автоматически отслеживать прогресс цели через транзакции.

**Пример use case:** Пользователь хочет накопить 50 000 ₽ на ремонт. Он связывает цель с категорией «Дом». Каждый раз когда он добавляет транзакцию типа «доход» с категорией «Дом» (или вручную помечает транзакцию как «взнос в цель») — прогресс цели обновляется автоматически.

### User Story

> Как пользователь, я хочу связать финансовую цель с категорией расходов или доходов, чтобы автоматически отслеживать прогресс накопления через транзакции.

### Функциональные требования

1. **Поле «Связанная категория»** в форме создания/редактирования цели (GoalDetailPage):
   - Picker из фиксированного списка категорий
   - Опционально (можно не выбирать)
   - Подсказка: «Транзакции этой категории будут автоматически учитываться в прогрессе цели»

2. **Два режима связи:**
   - **Накопление (savings):** доходные транзакции категории увеличивают `currentAmount` цели
   - **Контроль расходов (spending):** расходные транзакции категории уменьшают «доступный бюджет» цели (для целей типа «потратить не более X на ремонт»)

3. **Автоматическое обновление прогресса:**
   - При добавлении транзакции с категорией, связанной с целью → `currentAmount` обновляется
   - Только транзакции после даты создания связи учитываются

4. **Индикатор на GoalDetailPage:** «Связана с категорией: 🏠 Дом (накопление)»

5. **История взносов:** список транзакций, которые повлияли на прогресс цели (последние 10)

6. **Ручной взнос** остаётся доступным (кнопка «+ Добавить взнос» на GoalDetailPage)

### Файлы для изменения

### Обновление интерфейса Goal

```typescript
// Уже существует в store.ts:
interface Goal {
  id: string;
  title: string;
  targetAmount: number;
  currentAmount: number;
  deadline?: string;
  // Новые поля:
  linkedCategoryId?: string;        // ID категории из фиксированного списка
  linkedCategoryMode?: 'savings' | 'spending'; // режим связи
  linkedSince?: string;             // ISO date — транзакции до этой даты не учитываются
}
```

### Acceptance Criteria

**AC-1:** Given форма создания цели, When пользователь выбирает «Связанная категория: Дом» и режим «Накопление», Then цель сохраняется с `linkedCategoryId = "home"` и `linkedCategoryMode = "savings"`

**AC-2:** Given цель связана с категорией «Дом» (накопление), When добавлена доходная транзакция с категорией «Дом» на 5 000 ₽, Then `currentAmount` цели увеличивается на 5 000 ₽

**AC-3:** Given цель связана с категорией «Дом» (накопление), When добавлена расходная транзакция с категорией «Дом», Then `currentAmount` цели НЕ изменяется

**AC-4:** Given цель связана с категорией, When GoalDetailPage открыта, Then отображается строка «Связана с: 🏠 Дом (накопление)»

**AC-5:** Given история взносов, When GoalDetailPage открыта, Then показываются последние 10 транзакций, повлиявших на прогресс цели

**AC-6:** Given транзакция добавлена до даты создания связи (`linkedSince`), When прогресс пересчитывается, Then эта транзакция НЕ учитывается

**AC-7:** Given цель без связанной категории, When GoalDetailPage открыта, Then строка «Связана с категорией» не отображается, только кнопка «+ Добавить взнос»

**AC-8:** Given связь удалена (пользователь убрал категорию), When GoalDetailPage открыта, Then `currentAmount` не изменяется (уже накопленное остаётся), новые транзакции больше не учитываются

### Edge Cases

- **Одна категория связана с несколькими целями:** транзакция обновляет все связанные цели
- **Цель достигнута (currentAmount >= targetAmount):** автоматические взносы прекращаются, показывается «🎉 Цель достигнута!»
- **Отрицательный `currentAmount`** (режим spending, расходы > targetAmount): показывается как 0, не уходит в минус
- **Удаление транзакции:** `currentAmount` пересчитывается (уменьшается на сумму удалённой транзакции)

### Метрики успеха

- **Primary:** % целей с привязанной категорией через 14 дней после релиза ≥ 20%
- **Guardrail:** % пользователей, у которых `currentAmount` расходится с реальными транзакциями = 0% (корректность расчёта)

### Явно вне скоупа

- Связь цели с несколькими категориями одновременно
- Автоматическое создание транзакции при ручном взносе в цель
- Цели типа «не тратить больше X» (только накопление в MVP)
