## 📋 ТЗ (Product Manager)

### Проблема пользователя

Пользователь не получает уведомлений о:
- Превышении бюджета по категории
- Предстоящих регулярных платежах (за 3 дня)
- Еженедельном финансовом отчёте

Без уведомлений пользователь не возвращается в приложение и теряет контроль над финансами.

### User Story

> Как пользователь, я хочу получать своевременные уведомления в Telegram о важных финансовых событиях, чтобы не пропускать платежи и не выходить за рамки бюджета.

### Функциональные требования

#### Типы уведомлений

1. **Превышение бюджета** — отправляется когда расходы по категории достигают 80% и 100% лимита
   - Текст: «⚠️ Вы потратили 80% бюджета на [категория]: [сумма] из [лимит] ₽»
   - Триггер: при добавлении новой транзакции через finance-service

2. **Напоминание о регулярном платеже** — за 3 дня до ожидаемого платежа
   - Текст: «📅 Через 3 дня ожидается платёж: [название] ~[сумма] ₽»
   - Триггер: cron каждый день в 10:00 UTC

3. **Еженедельный отчёт** — каждое воскресенье в 18:00 UTC
   - Текст: краткая сводка за неделю (доходы, расходы, топ-3 категории, SafeToSpend)
   - Генерируется через ai-service

#### Технические требования

4. **Telegram Bot API** — отправка сообщений через `sendMessage` с `chat_id = telegramId`
5. **Cron jobs** — `node-cron` для периодических задач
6. **Настройки уведомлений** — проверять флаги из finance-service перед отправкой (TASK-020)
7. **Retry logic** — при ошибке Telegram API повторить через 5 минут, максимум 3 попытки
8. **Логирование** — каждое отправленное уведомление логируется с `telegramId`, типом и временем

#### API эндпоинты

9. **POST /notify/budget-alert** — внутренний эндпоинт для вызова из finance-service
10. **POST /notify/test** — тестовая отправка уведомления (только для dev-окружения)
11. **GET /health** — `{ "status": "ok", "service": "notification-service" }`

### Технический стек

- Fastify + TypeScript (уже настроен в `services/notification-service/`)
- `node-cron` для cron jobs
- Telegram Bot API (HTTP, без SDK)
- Порт: 3004 (см. `docker-compose.yml`)
- Переменные окружения: `BOT_TOKEN`, `FINANCE_SERVICE_URL`, `AI_SERVICE_URL`, `JWT_SECRET`

### Файлы для изменения

- `services/notification-service/src/index.ts` — основная реализация
- `services/notification-service/package.json` — добавить `node-cron`
- `services/finance-service/src/index.ts` — добавить вызов notification-service при превышении бюджета

### Acceptance Criteria

**AC-1:** Given расходы по категории достигли 80% лимита, When транзакция добавлена через finance-service, Then пользователь получает Telegram-сообщение в течение 30 секунд

**AC-2:** Given регулярный платёж с dayOfMonth = 15, When текущая дата = 12-е число, Then cron в 10:00 UTC отправляет напоминание

**AC-3:** Given воскресенье 18:00 UTC, When cron срабатывает, Then все пользователи с включёнными еженедельными отчётами получают сводку

**AC-4:** Given Telegram API вернул ошибку 429 (rate limit), When retry logic срабатывает, Then повторная попытка через 5 минут, максимум 3 раза

**AC-5:** Given пользователь отключил уведомления о бюджете (TASK-020), When бюджет превышен, Then уведомление НЕ отправляется

**AC-6:** Given POST /notify/test в dev-окружении, When запрос выполнен, Then тестовое сообщение отправлено в Telegram пользователя

**AC-7:** Given `BOT_TOKEN` не задан, When сервис стартует, Then процесс завершается с ошибкой

**AC-8:** Given отправленное уведомление, When проверить логи, Then запись содержит `telegramId`, тип уведомления, время отправки и статус

### Edge Cases

- **Пользователь заблокировал бота:** Telegram вернёт 403, уведомление помечается как недоставленное, повторные попытки прекращаются
- **Несколько превышений бюджета одновременно:** отправляется одно сообщение со списком категорий
- **Пользователь без настроек уведомлений:** используются настройки по умолчанию (все уведомления включены)
- **Cron в разных часовых поясах:** все cron jobs в UTC, пользователь видит время в своём часовом поясе (ASSUMPTION — нужна валидация)

### Метрики успеха

- **Primary:** % пользователей, открывших приложение после получения уведомления ≥ 25% (CTR уведомлений)
- **Guardrail:** % недоставленных уведомлений < 5%

### Явно вне скоупа

- Push-уведомления через браузер (только Telegram Bot)
- Настройка времени уведомлений пользователем (Sprint 4, TASK-020)
- Email-уведомления
- Rich media в уведомлениях (фото, кнопки — добавить в Sprint 3)
