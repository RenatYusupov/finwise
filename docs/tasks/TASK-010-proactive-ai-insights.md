## 📋 ТЗ (Product Manager)

### Проблема пользователя

Dashboard показывает только текущее состояние (SafeToSpend, цели, последние транзакции), но не даёт пользователю проактивных подсказок. Пользователь не знает:
- Что его расходы на кафе выросли на 40% по сравнению с прошлым месяцем
- Что он тратит больше всего по пятницам
- Что при текущем темпе трат он выйдет за рамки бюджета через 5 дней

**ASSUMPTION — нужна валидация:** пользователи хотят видеть инсайты на главном экране, а не только в AI-чате.

### User Story

> Как пользователь, я хочу видеть на главном экране персонализированные финансовые инсайты, чтобы замечать паттерны в своих тратах без необходимости самостоятельно анализировать данные.

### Функциональные требования

1. **Карточка инсайта** на Dashboard между SafeToSpendCard и быстрыми действиями
2. **Ротация инсайтов** — показывается один инсайт, свайп влево/вправо переключает между 3 инсайтами
3. **Типы инсайтов:**
   - `warning` (🔴) — превышение паттерна: «Расходы на кафе +40% vs прошлый месяц»
   - `tip` (💡) — полезный совет: «Вы тратите больше по пятницам»
   - `positive` (✅) — позитивное подкрепление: «Отличная неделя! Расходы на 15% ниже нормы»
   - `forecast` (📊) — прогноз: «При текущем темпе бюджет закончится 25-го»
4. **Источник данных:** GET /ai/insights из TASK-007 (или локальный расчёт если бэкенд недоступен)
5. **Fallback без бэкенда:** локальный расчёт 2–3 простых инсайтов на основе данных в store (топ категория, сравнение с прошлой неделей)
6. **Обновление:** инсайты обновляются при открытии приложения, кэшируются на 6 часов
7. **Dismiss:** кнопка «✕» скрывает карточку до следующего обновления
8. **Tap to chat:** тап на инсайт открывает AI-чат с предзаполненным вопросом по теме инсайта

### UI-спецификация

```
┌─────────────────────────────────────┐
│ 💡 Инсайт                      [✕] │
│                                     │
│ Расходы на кафе выросли на 40%      │
│ по сравнению с прошлым месяцем      │
│                                     │
│ ● ○ ○  [Обсудить с AI →]           │
└─────────────────────────────────────┘
```

- Фон: градиент по типу (warning=оранжевый, tip=синий, positive=зелёный, forecast=фиолетовый)
- Dots-индикатор для навигации между инсайтами
- Анимация появления: fade-in + slide-up (Framer Motion)

### Acceptance Criteria

**AC-1:** Given пользователь открывает Dashboard с ≥30 транзакциями, When страница загружена, Then карточка инсайта отображается с текстом и иконкой типа

**AC-2:** Given карточка с 3 инсайтами, When пользователь свайпает влево, Then показывается следующий инсайт с анимацией slide

**AC-3:** Given тап на «Обсудить с AI →», When переход выполнен, Then открывается AiChatPage с предзаполненным сообщением, связанным с темой инсайта

**AC-4:** Given нажатие «✕», When карточка закрыта, Then карточка скрывается и не появляется до следующего открытия приложения (или 6 часов)

**AC-5:** Given бэкенд недоступен, When Dashboard открыт, Then отображается локально рассчитанный инсайт (топ категория расходов за текущий месяц)

**AC-6:** Given пользователь с < 5 транзакциями, When Dashboard открыт, Then карточка инсайта НЕ отображается (недостаточно данных)

**AC-7:** Given инсайт типа `warning`, When карточка отображается, Then фон оранжевый/красный, иконка 🔴

**AC-8:** Given инсайты загружены 5 часов назад, When пользователь открывает приложение, Then используются кэшированные инсайты (не делается новый запрос)

### Edge Cases

- **Нет транзакций:** карточка не отображается
- **Только 1 инсайт:** dots-индикатор не отображается
- **Очень длинный текст инсайта:** обрезается до 2 строк с «...»
- **Ошибка загрузки инсайтов:** карточка не отображается (не показывать ошибку пользователю)

### Метрики успеха

- **Primary:** % пользователей, тапнувших на инсайт (CTR карточки) ≥ 15%
- **Guardrail:** карточка не увеличивает время загрузки Dashboard > 100ms

### Явно вне скоупа

- Персонализация типов инсайтов пользователем
- Инсайты в push-уведомлениях (TASK-009)
- A/B тест разных форматов карточки
