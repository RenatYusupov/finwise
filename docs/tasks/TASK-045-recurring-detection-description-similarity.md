## 📋 ТЗ (заполняет PM)

### Проблема

После TASK-035 алгоритм `detectRecurringPayments` по-прежнему показывает очевидно не регулярные транзакции в PostImportWizard. Пользователь видит ложных кандидатов → теряет доверие → не подтверждает ничего → `reservedUpcoming = 0` → SafeToSpend работает без резервирования → дневной лимит завышен.

Две симметричные проблемы:
- **False positives:** случайные платежи 1400₽ и 1550₽ с разными описаниями («Бургер Кинг», «DNS Техника», «Wildberries») кластеризуются — алгоритм смотрит только на сумму ±15% и день ±7, игнорирует описание
- **False negatives:** реальная аренда 35 000₽ с разными описаниями («Аренда квартиры», «Оплата жилья», «Перевод хозяйке») не кластеризуется — description similarity < 0.5, хотя категория `home` одинаковая

ALGORITHM_SPEC.md ALG-001 (Изменение 2) предписывает description similarity как первичный ключ кластеризации — не реализовано.

### Решение

Два пути попадания транзакции в кластер:

**Путь 1 — одинаковый сервис/подписка (description similarity):**
```
descriptionSimilarity(tx.description, cluster.label) ≥ 0.5
```
Нормализация: lowercase, убрать цифры и спецсимволы, сравнить долю общих слов длиной > 2 символов.

**Путь 2 — регулярная категория (category-based):**
```
tx.categoryId === cluster.categoryId
AND tx.categoryId ∈ RECURRING_CATEGORIES
```
`RECURRING_CATEGORIES = { home, health, education, transport, telecom }`

Оба пути дополнительно требуют: сумма ±15%, день ±7 (существующая логика).

**Дополнительные фиксы:**
- MVP: добавить `other_exp` в `EXCLUDE_CATEGORIES` — catch-all категория генерирует ~30% ложных кандидатов
- MVP: consecutive months check — разрыв между соседними месяцами кластера не более 2 месяцев (транзакции в январе, апреле, июле → gap=2 → не регулярные)

**Out of scope:**
- Адаптивный DAY_TOLERANCE (10 для конца месяца) — отдельная задача
- Пересчёт confidence на основе consistency описания — отдельная задача
- Изменение UI RecurringPage и PostImportWizard

### Acceptance Criteria

- [ ] **AC-1:** Транзакции с `descriptionSimilarity < 0.5` и разными категориями (или категорией вне `RECURRING_CATEGORIES`) НЕ попадают в один кластер, даже если сумма ±15% и день ±7.
- [ ] **AC-2:** Аренда 35 000₽ с описаниями «Аренда квартиры», «Оплата жилья», «Перевод хозяйке» (категория `home`) за 3 месяца подряд → попадает в кандидаты.
- [ ] **AC-3:** Транзакции категории `other_exp` не попадают в кандидаты (добавлена в `EXCLUDE_CATEGORIES`).
- [ ] **AC-4:** Кластер из транзакций в январе, апреле, июле (gap = 2 месяца) → НЕ квалифицируется как регулярный.
- [ ] **AC-5:** Яндекс Плюс 299₽ × 3 месяца подряд (subscription whitelist) → по-прежнему попадает в кандидаты (регрессия не допускается).
- [ ] **AC-6:** Аренда 35 000₽ и кредит 34 500₽ (разница 1.4%, но разные категории и разные описания) → НЕ сливаются в один кластер.
