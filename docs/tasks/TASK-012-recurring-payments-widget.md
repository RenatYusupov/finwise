## 📋 ТЗ (Product Manager)

### Проблема пользователя

Пользователь не видит на главном экране сколько денег уйдёт на регулярные платежи в ближайшие дни. Это приводит к тому, что SafeToSpend кажется больше реального — пользователь не учитывает предстоящие обязательные расходы.

### User Story

> Как пользователь, я хочу видеть на Dashboard виджет с ближайшими регулярными платежами, чтобы понимать сколько денег реально свободно с учётом обязательных расходов.

### Функциональные требования

1. **Виджет «Ближайшие платежи»** на Dashboard — показывает регулярные платежи в ближайшие 7 дней
2. **Список платежей** в виджете: название, сумма, дата («через 2 дня», «завтра», «сегодня»)
3. **Итоговая строка:** «Итого в ближайшие 7 дней: X ₽»
4. **Если нет платежей** в ближайшие 7 дней: виджет не отображается
5. **Тап на виджет** → переход на `/recurring` (TASK-008)
6. **Максимум 3 платежа** в виджете, остальные скрыты с «+N ещё»
7. **Цветовая индикация:** платёж сегодня — красный, завтра — оранжевый, остальные — серый

### Файлы для изменения

- `apps/web/src/pages/dashboard/DashboardPage.tsx` — добавить виджет
- `apps/web/src/features/finance/store.ts` — добавить селектор `getUpcomingPayments(days: number)`

### Acceptance Criteria

**AC-1:** Given активные регулярные платежи с dayOfMonth в ближайшие 7 дней, When Dashboard открыт, Then виджет отображается со списком платежей

**AC-2:** Given платёж сегодня (dayOfMonth = текущий день), When виджет отображается, Then строка платежа выделена красным с текстом «Сегодня»

**AC-3:** Given более 3 платежей в ближайшие 7 дней, When виджет отображается, Then показываются первые 3 и строка «+N ещё»

**AC-4:** Given тап на виджет, When переход выполнен, Then открывается `/recurring`

**AC-5:** Given нет активных платежей в ближайшие 7 дней, When Dashboard открыт, Then виджет не отображается (не занимает место)

**AC-6:** Given итоговая строка, When виджет отображается, Then сумма корректно суммирует все платежи в ближайшие 7 дней

### Edge Cases

- **dayOfMonth = 31 в месяце с 30 днями:** считается как последний день месяца
- **Платёж уже прошёл в этом месяце:** не показывается (следующий — в следующем месяце)
- **Нет регулярных платежей вообще:** виджет не отображается

### Метрики успеха

- **Primary:** % пользователей, перешедших на экран регулярных платежей через виджет ≥ 10%
- **Guardrail:** виджет не увеличивает время загрузки Dashboard > 50ms

### Явно вне скоупа

- Отметка платежа как «оплачен» прямо из виджета
- Изменение суммы платежа из виджета
