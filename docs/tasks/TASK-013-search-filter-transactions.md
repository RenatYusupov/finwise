## 📋 ТЗ (Product Manager)

### Проблема пользователя

При большом количестве транзакций (100+) пользователь не может быстро найти нужную. Нет возможности отфильтровать по категории, периоду или сумме. Поиск по описанию отсутствует.

### User Story

> Как пользователь, я хочу искать транзакции по тексту и фильтровать по категории, периоду и типу, чтобы быстро находить нужные записи и анализировать конкретные расходы.

### Функциональные требования

1. **Строка поиска** в верхней части TransactionsPage — поиск по описанию транзакции (case-insensitive, substring match)
2. **Фильтр-панель** — открывается по кнопке «Фильтры» рядом со строкой поиска, содержит:
   - Тип: «Все» / «Расходы» / «Доходы»
   - Категория: мультиселект из фиксированного списка категорий
   - Период: «Эта неделя» / «Этот месяц» / «Прошлый месяц» / «Произвольный» (date range picker)
   - Сумма: «от» и «до» (number inputs)
3. **Активные фильтры** отображаются как chips под строкой поиска, каждый chip можно удалить
4. **Счётчик результатов:** «Найдено: N транзакций» под строкой поиска
5. **Сортировка:** по дате (новые/старые), по сумме (больше/меньше) — dropdown
6. **Пустой результат:** «Ничего не найдено. Попробуйте изменить фильтры» с кнопкой «Сбросить фильтры»
7. **Поиск в реальном времени** — debounce 300ms, фильтрация на клиенте (не запрос к серверу)
8. **Сохранение последних фильтров** в sessionStorage (сбрасываются при закрытии приложения)

### Acceptance Criteria

**AC-1:** Given строка поиска, When пользователь вводит «пятёрочка», Then список фильтруется по описанию (case-insensitive) с debounce 300ms

**AC-2:** Given фильтр по категории «Кафе», When применён, Then показываются только транзакции с `category = "cafe"`, появляется chip «Кафе ✕»

**AC-3:** Given фильтр «Этот месяц», When применён, Then показываются транзакции только за текущий календарный месяц

**AC-4:** Given активный chip фильтра, When пользователь нажимает «✕» на chip, Then этот фильтр снимается, список обновляется

**AC-5:** Given несколько активных фильтров, When нажата «Сбросить фильтры», Then все фильтры сняты, строка поиска очищена

**AC-6:** Given фильтры применены и результат пустой, When отображается пустой список, Then показывается сообщение «Ничего не найдено» с кнопкой «Сбросить фильтры»

**AC-7:** Given сортировка «По сумме (больше)», When применена, Then транзакции отсортированы по убыванию суммы

**AC-8:** Given произвольный период, When пользователь выбирает «с 01.05 по 15.05», Then показываются транзакции только за этот диапазон

### Edge Cases

- **Поиск по пустой строке:** показываются все транзакции (фильтр не применяется)
- **Фильтр суммы «от» > «до»:** поле «до» подсвечивается ошибкой
- **Очень длинный поисковый запрос (>100 символов):** обрезается до 100 символов
- **Нет транзакций вообще:** строка поиска и фильтры отображаются, но список пустой с CTA «Добавить транзакцию»
- **Мобильная клавиатура:** при открытии клавиатуры список скроллируется, строка поиска остаётся видимой

### Метрики успеха

- **Primary:** % пользователей, использующих поиск/фильтры хотя бы раз в неделю ≥ 20%
- **Guardrail:** время фильтрации 1000 транзакций < 50ms (клиентская фильтрация)

### Явно вне скоупа

- Полнотекстовый поиск на сервере (достаточно клиентской фильтрации для MVP)
- Сохранение именованных фильтров («Мои фильтры»)
- Поиск по сумме с нечётким совпадением
