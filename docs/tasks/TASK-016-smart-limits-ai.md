## 📋 ТЗ (Product Manager)

### Проблема пользователя

Пользователь устанавливает бюджеты вручную, не зная какие лимиты реалистичны для него. Он либо ставит слишком жёсткие лимиты (постоянно превышает, теряет мотивацию) или слишком мягкие (бюджет не помогает экономить).

**ASSUMPTION — нужна валидация:** пользователи готовы принять AI-рекомендацию бюджета, а не устанавливать его самостоятельно.

### User Story

> Как пользователь, я хочу получить AI-рекомендацию бюджета по каждой категории на основе моей истории трат, чтобы установить реалистичные лимиты без ручного анализа.

### Функциональные требования

1. **Кнопка «✨ Умные лимиты»** на BudgetPage — запускает генерацию рекомендаций
2. **Алгоритм рекомендации** (на ai-service):
   - Берёт медиану расходов по категории за последние 3 месяца
   - Применяет коэффициент снижения: -10% от медианы (цель — небольшая экономия)
   - Округляет до ближайших 500 ₽
   - Если данных < 2 месяца — не рекомендует для этой категории
3. **Экран рекомендаций** — список категорий с предложенными лимитами:
   - Название категории + иконка
   - «Текущий лимит: X ₽» (если уже установлен) или «Не установлен»
   - «Рекомендуется: Y ₽» (на основе истории)
   - «Среднее за 3 мес: Z ₽» (для прозрачности)
   - Checkbox «Применить» (по умолчанию включён для категорий без лимита)
4. **Кнопка «Применить выбранные»** — устанавливает лимиты для отмеченных категорий
5. **Объяснение рекомендации** — тап на «?» рядом с суммой показывает: «Рассчитано на основе ваших трат за 3 месяца: апрель 5 800 ₽, март 6 200 ₽, февраль 5 400 ₽. Рекомендуем снизить на 10%»
6. **Ручная корректировка** — пользователь может изменить рекомендованную сумму перед применением

### Acceptance Criteria

**AC-1:** Given пользователь с ≥2 месяцами истории, When нажата «✨ Умные лимиты», Then через ≤3 секунды отображается список рекомендаций

**AC-2:** Given рекомендация для категории «Кафе» с медианой 6 000 ₽, When отображается, Then рекомендованный лимит = 5 400 ₽ (медиана × 0.9, округлено до 500)

**AC-3:** Given категория с данными < 2 месяцев, When рекомендации отображаются, Then эта категория помечена «Недостаточно данных» и не имеет checkbox

**AC-4:** Given пользователь изменил рекомендованную сумму вручную, When нажата «Применить выбранные», Then устанавливается изменённая сумма, не оригинальная рекомендация

**AC-5:** Given нажата «Применить выбранные» с 3 отмеченными категориями, When операция выполнена, Then 3 бюджета обновлены в store, показывается toast «Лимиты обновлены»

**AC-6:** Given тап на «?» рядом с рекомендацией, When tooltip открыт, Then показывается объяснение с историей по месяцам

**AC-7:** Given пользователь с < 2 месяцами истории, When нажата «✨ Умные лимиты», Then показывается сообщение «Нужно минимум 2 месяца данных для рекомендаций. Сейчас доступно: 1 месяц»

**AC-8:** Given ai-service недоступен, When нажата «✨ Умные лимиты», Then показывается ошибка «Не удалось загрузить рекомендации. Попробуйте позже»

### Edge Cases

- **Категория с нулевыми расходами:** рекомендация не генерируется
- **Категория «Доходы»:** не включается в рекомендации (только расходные категории)
- **Все категории уже имеют лимиты:** checkboxes по умолчанию выключены, пользователь выбирает сам
- **Рекомендованный лимит < 500 ₽:** устанавливается минимум 500 ₽

### Метрики успеха

- **Primary:** % пользователей, применивших хотя бы 1 AI-рекомендацию бюджета ≥ 30%
- **Guardrail:** % пользователей, изменивших рекомендацию перед применением ≤ 40% (если больше — рекомендации нерелевантны)

### Явно вне скоупа

- Динамическое обновление лимитов в течение месяца
- Рекомендации на основе целей пользователя (Sprint 4)
- A/B тест коэффициента снижения (10% vs 15% vs 20%)
