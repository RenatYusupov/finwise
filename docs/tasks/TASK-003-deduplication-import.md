## 📋 ТЗ (заполняет PM)

### Проблема

Повторный импорт одного и того же файла выписки создаёт дубликаты транзакций. Пользователь, который импортирует выписку дважды (случайно или намеренно), получает задвоенные расходы — SafeToSpend показывает вдвое меньше, чем есть на самом деле. Это разрушает доверие к продукту.

### Решение

Перед добавлением каждой транзакции при импорте — проверка на дубликат по детерминированному ключу `date|amount|description`. Дубликаты пропускаются с подсчётом счётчика.

### Затрагиваемые файлы

- `apps/web/src/features/finance/store.ts` — добавить `isDuplicate()` проверку в `addTransaction()` или создать `addTransactionsBatch()`
- `apps/web/src/pages/profile/ProfilePage.tsx` — обновить UI результата импорта (показать счётчик дубликатов)
- `apps/web/src/pages/profile/bankImport.ts` — возможно, генерировать детерминированный `id` на основе хэша

### Acceptance Criteria

- [ ] AC-1: При импорте каждая транзакция проверяется на дубликат по ключу `${date.slice(0,10)}|${amount}|${description.slice(0,50)}`
- [ ] AC-2: Дубликаты пропускаются, счётчик `skipped` увеличивается
- [ ] AC-3: В результате импорта показывается: "Импортировано: X, Пропущено дубликатов: Y"
- [ ] AC-4: Пользователь может принудительно импортировать дубликаты через чекбокс "Включить дубликаты" (по умолчанию выключен)
- [ ] AC-5: Дедупликация работает для всех форматов: XLSX (Альфа, Сбер, Т-Банк), PDF (Т-Банк)
- [ ] AC-6: Повторный импорт того же файла → 0 новых транзакций, все пропущены как дубликаты

### Метрики успеха

- **Primary**: 0 дублирующихся транзакций после повторного импорта одного файла
- **Guardrail**: время импорта 1000 транзакций не увеличивается более чем на 10%
