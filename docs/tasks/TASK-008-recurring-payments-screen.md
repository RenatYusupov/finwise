## 📋 ТЗ (Product Manager)

### Проблема пользователя

Алгоритм автоматически обнаруживает регулярные платежи (подписки, аренда, коммуналка), но пользователь не может:
- Видеть список обнаруженных регулярных платежей
- Подтвердить или отклонить автоматически обнаруженный платёж
- Добавить регулярный платёж вручную
- Видеть сколько денег уходит на регулярные платежи в месяц

**Validated user problem:** Из анализа данных (MANDATORY_PAYMENTS_ANALYSIS.md) — у пользователя есть регулярные платежи (телефон, интернет, образование), но алгоритм не всегда их обнаруживает с высокой уверенностью.

### User Story

> Как пользователь, я хочу видеть список всех регулярных платежей и управлять ими, чтобы понимать сколько денег зарезервировано каждый месяц и не пропустить важный платёж.

### Функциональные требования

1. **Новый экран `/recurring`** — список регулярных платежей, разделённый на секции:
   - «Подтверждённые» (active: true, confidence ≥ 0.7 или подтверждены вручную)
   - «Требуют подтверждения» (active: true, confidence < 0.7)
   - «Неактивные» (active: false — устаревшие, скрытые по умолчанию)

2. **Карточка регулярного платежа** отображает:
   - Название (label)
   - Сумма и день месяца («~5 200 ₽ · 15-го числа»)
   - Категория (иконка + название)
   - Confidence badge (только для автообнаруженных)
   - Кнопки: «✓ Подтвердить» (для неподтверждённых), «✏️ Изменить», «🗑️ Удалить»

3. **Добавление вручную** — FAB «+» открывает форму:
   - Название (text)
   - Сумма (number)
   - День месяца (1–31, picker)
   - Категория (picker)

4. **Итоговая строка** внизу экрана: «Итого в месяц: X ₽» — сумма всех активных регулярных платежей

5. **Навигация:** добавить пункт «Регулярные» в BottomNav или как отдельный раздел в ProfilePage

6. **Haptic feedback** при подтверждении и удалении

### Acceptance Criteria

**AC-1:** Given список регулярных платежей в store, When пользователь открывает `/recurring`, Then видит все активные платежи, разделённые на «Подтверждённые» и «Требуют подтверждения»

**AC-2:** Given платёж с confidence < 0.7, When пользователь нажимает «✓ Подтвердить», Then платёж перемещается в секцию «Подтверждённые», confidence badge исчезает

**AC-3:** Given нажатие «+», When пользователь заполняет форму и сохраняет, Then новый регулярный платёж появляется в списке «Подтверждённые» с confidence = 1.0

**AC-4:** Given список платежей, When пользователь нажимает «🗑️ Удалить» и подтверждает, Then платёж удаляется из store и исчезает из списка

**AC-5:** Given несколько активных платежей, When экран открыт, Then в нижней строке отображается корректная сумма «Итого в месяц: X ₽»

**AC-6:** Given пустой список регулярных платежей, When экран открыт, Then отображается empty state «Регулярные платежи не обнаружены. Добавьте вручную или импортируйте выписку из банка»

**AC-7:** Given форма добавления, When пользователь вводит день месяца > 31 или < 1, Then поле подсвечивается ошибкой «День должен быть от 1 до 31»

**AC-8:** Given экран на мобильном устройстве, When список длинный, Then список скроллируется, итоговая строка зафиксирована внизу (sticky footer)

### Edge Cases

- **Нет регулярных платежей:** empty state с CTA «Импортировать выписку»
- **Платёж с dayOfMonth = 31 в феврале:** отображается как «последнее число месяца»
- **Очень длинное название:** обрезается до 40 символов с «...»
- **Сумма 0:** не допускается при ручном добавлении

### Метрики успеха

- **Primary:** % пользователей с ≥1 подтверждённым регулярным платежом через 14 дней после релиза ≥ 30%
- **Guardrail:** время открытия экрана < 200ms

### Явно вне скоупа

- Push-уведомления о предстоящих платежах (TASK-009)
- Виджет регулярных платежей на Dashboard (TASK-012)
- Автоматическое списание (не финансовый инструмент)
- Интеграция с банковскими подписками
