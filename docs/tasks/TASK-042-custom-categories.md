## 📋 ТЗ (заполняет PM)

### Проблема

Пользователь не может добавить категорию, которой нет в системном списке. Расходы на питомца, ребёнка, автосервис, хобби — всё падает в «Другое» (`other_exp`). Аналитика не отражает реальную структуру расходов.

Список категорий захардкожен в `EXPENSE_CATEGORIES` / `INCOME_CATEGORIES` в `store.ts`. Компоненты `AddTransactionPage` и `TransactionsPage` используют эти массивы напрямую без точки расширения.

### Решение

Добавить возможность создавать кастомные категории через кнопку в пикере категорий. Хранить в Zustand store (persist).

**Флоу:**
1. Пользователь открывает пикер категорий (добавление / редактирование транзакции)
2. В конце списка — кнопка «+ Создать категорию»
3. Открывается bottom sheet с формой: название + emoji + тип (расход / доход)
4. После сохранения — категория появляется в пикере, сразу выбирается

**Управление кастомными категориями:**
- Удаление — из профиля или из самого пикера (long-press или кнопка «✕»)
- Нельзя удалить, если есть транзакции с этой категорией — показать предупреждение
- Системные категории (18 штук) изменить / удалить нельзя

**Ограничения MVP (явные):**
- При импорте из банка кастомные категории не используются для автокатегоризации — транзакции по-прежнему остаются в `other_exp`. Пользователь может вручную перекатегоризировать через RecategorizationSheet.
- Цвет генерируется автоматически из палитры (не пикер)
- Максимум 20 кастомных категорий

### Что сделано

- **store.ts**: добавлены `customCategories: Category[]`, `addCustomCategory` (возвращает новый id), `deleteCustomCategory`. Модуль-уровневый кэш `_customCategoryCache` синхронизируется через `onRehydrateStorage` — `getCategoryById` теперь находит кастомные категории для всех операций store.
- **CreateCategorySheet.tsx**: новый shared компонент — bottom sheet с name input (≤20 символов), grid из 30 emoji-пресетов, превью карточки, авто-цвет из палитры. Проверяет лимит 20 категорий.
- **AddTransactionPage.tsx**: пикер категорий включает кастомные, кнопка «+ Создать категорию», ✕ кнопка на кастомных (с подтверждением через Telegram.showConfirm).
- **TransactionsPage.tsx**: EditTransactionSheet — аналогичные изменения, CreateCategorySheet рендерится через Fragment + отдельный портал.

### Что НЕ сделано (если есть)

- Кастомные категории не синхронизируются в CloudStorage (только localStorage). Между устройствами не переносятся. Добавить в CloudPayload — следующий шаг.
- Управление категориями из ProfilePage не реализовано (можно удалить только из пикера).

### Риски и известные ограничения

- При импорте из банка кастомные категории не используются для авто-категоризации (per spec).
- `getCategoryById` fallback для аналитики работает корректно — кастомные категории находятся через `_customCategoryCache`.

### Тестирование

1. Открыть «Добавить транзакцию» → выбрать тип «Расход» → в пикере категорий нажать «+ Создать категорию»
2. Ввести название «Питомец», emoji «🐾» → сохранить
3. Убедиться, что «Питомец» появился в пикере и автоматически выбран
4. Сохранить транзакцию → в аналитике должна появиться категория «Питомец»
5. Закрыть и переоткрыть приложение → «Питомец» должен быть в пикере
6. Попробовать удалить «Питомец» при наличии транзакции → должно появиться предупреждение
7. Попробовать удалить системную категорию «Еда» → кнопки удаления нет
