## 📋 ТЗ (заполняет PM)

### Проблема

После TASK-044 (удаление «Регулярные» из BottomNav) единственный путь к `/recurring` — карточка «Ближайшие платежи» на главной. Но она скрывается при `confirmed.length === 0` (return null). Активный пользователь без подтверждённых платежей не может попасть в раздел управления регулярными платежами вообще.

Два симптома:
1. Новый пользователь хочет настроить регулярные платежи вручную → некуда нажать
2. Пользователь ищет раздел в Profile (логичное место для управления) → его нет

### Решение

**MVP: два входа в `/recurring`:**

① **Dashboard — пустое состояние виджета:**  
При `confirmed.length === 0` вместо `return null` показывать компактную однострочную заглушку:
```
🔁 Регулярные платежи    [Настроить →]
```
Минималистичная карточка, меньше по визуальному весу, чем заполненный вариант.

② **ProfilePage — новый пункт в разделе управления:**  
Добавить строку «🔁 Регулярные платежи» рядом с блоком импорта выписки / управления данными. Тап → `navigate('/recurring')`.

**Out of scope:**
- Возврат «Регулярные» в BottomNav
- Изменение самого `/recurring` экрана
- Счётчик/бейдж на пустом состоянии

### Затрагиваемые файлы

- `apps/web/src/pages/dashboard/DashboardPage.tsx` — `UpcomingPaymentsWidget`: убрать `return null`, добавить пустое состояние
- `apps/web/src/pages/profile/ProfilePage.tsx` — добавить пункт навигации к `/recurring`

### Acceptance Criteria

- [ ] **AC-1:** При 0 подтверждённых регулярных платежах на главной видна компактная строка «🔁 Регулярные платежи · Настроить →» (не пустой экран).
- [ ] **AC-2:** Тап по этой строке ведёт на `/recurring`.
- [ ] **AC-3:** При наличии подтверждённых платежей виджет отображается в полном виде (регрессии нет).
- [ ] **AC-4:** В ProfilePage есть кнопка/строка «🔁 Регулярные платежи», ведущая на `/recurring`.
