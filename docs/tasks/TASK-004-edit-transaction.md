## 📋 ТЗ (Product Manager)

### Проблема пользователя

Пользователь не может исправить ошибочно добавленную транзакцию или изменить категорию после импорта из банка. Единственный вариант — удалить и добавить заново, что неудобно и приводит к потере данных (заметок, флагов).

**Validated user problem:** Пользователи импортируют выписки из банка, где P2P-переводы и снятия наличных требуют ручной классификации (ALG-004). Без редактирования они не могут завершить этот процесс.

### User Story

> Как пользователь, я хочу свайпнуть транзакцию влево и увидеть кнопки «Изменить» и «Удалить», чтобы быстро исправить категорию или сумму без необходимости удалять и создавать заново.

### Функциональные требования

1. **Свайп влево** на карточке транзакции в `TransactionsPage` открывает action-панель с двумя кнопками: «✏️ Изменить» и «🗑️ Удалить»
2. **Кнопка «Изменить»** открывает bottom sheet / модальное окно с формой редактирования
3. **Форма редактирования** содержит поля:
   - Сумма (number input)
   - Категория (picker из фиксированного списка категорий)
   - Описание (text input)
   - Дата (date picker)
   - Тип (доход / расход)
4. **После сохранения** транзакция обновляется в store, флаг `userCorrected: true` выставляется если изменена категория
5. **Кнопка «Удалить»** показывает confirm dialog, после подтверждения удаляет транзакцию
6. **Свайп закрывается** при тапе вне панели или при скролле списка
7. **Haptic feedback** при открытии action-панели и при успешном сохранении

### Acceptance Criteria

**AC-1:** Given транзакция в списке, When пользователь свайпает влево на ≥50px, Then появляется панель с кнопками «Изменить» и «Удалить» (красная)

**AC-2:** Given открытая панель редактирования, When пользователь меняет категорию и нажимает «Сохранить», Then транзакция обновляется в store с `userCorrected: true`

**AC-3:** Given открытая панель редактирования, When пользователь меняет только сумму или описание (не категорию), Then `userCorrected` остаётся `false` (не перезаписывает предыдущее значение)

**AC-4:** Given кнопка «Удалить», When пользователь нажимает, Then появляется confirm dialog «Удалить транзакцию?» с кнопками «Отмена» и «Удалить»

**AC-5:** Given confirm dialog, When пользователь подтверждает удаление, Then транзакция удаляется из store и исчезает из списка с анимацией

**AC-6:** Given открытая action-панель, When пользователь тапает вне панели или начинает скролл, Then панель закрывается

**AC-7:** Given форма редактирования, When пользователь вводит сумму ≤ 0, Then кнопка «Сохранить» заблокирована с сообщением «Сумма должна быть больше 0»

**AC-8:** Given Telegram WebView, When форма открыта с клавиатурой, Then форма не перекрывается клавиатурой (safe-area + keyboard-aware layout)

### Edge Cases

- **Пустой список:** кнопка «Изменить» недоступна (нет транзакций)
- **Транзакция с `requiresUserInput: true`:** после редактирования категории флаг сбрасывается в `false`
- **Одновременный свайп двух карточек:** при свайпе новой карточки предыдущая закрывается
- **Очень длинное описание:** обрезается до 200 символов в форме
- **Mobile:** форма занимает 90% высоты экрана, скроллируется внутри

### Метрики успеха

- **Primary:** % транзакций с `userCorrected: true` через 7 дней после релиза ≥ 5% от всех импортированных
- **Guardrail:** время открытия формы редактирования < 300ms (нет лагов анимации)

### Явно вне скоупа

- Bulk-редактирование нескольких транзакций одновременно
- История изменений транзакции
- Редактирование транзакций из бэкенда (только локальный store)
